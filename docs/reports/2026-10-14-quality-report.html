Key points

  • Options is a real settings page now. Sections are grouped (General, AI, Developer), every setting is a card with a title, one line and a control at the right, sub-options open in a one-level expander, and Live Reload lives in Options, Projects. The old Developer page is gone.
  • The design audit found real bugs, not just taste. The app was unusable in a narrow window (the 300px sidebar pushed every page out of view), no dialog closed with Esc, a wrong MCP secret returned a 400 page instead of a 401, and the New Project dialog used checkboxes for on and off settings.
  • Home no longer looks like a landing page. The gradient banner, the dictionary paragraph and the 72px icon tiles are replaced by a quiet header, tools grouped by name, favorites, a Get Started list and What's New.
  • The assistant can ask, learn and edit itself. It asks with a clickable card when there are clear options, writes one-line lessons when corrected (you can edit them), and can change its own character after you allow it.
  • The rules now have 26 named checks. Your list is in docs/ui-guidelines.md as What to avoid (A1 to A15, B1 to B11), adapted to a dense desktop tool, plus new rules from what the audit found twice.
  • Every behavior check passes after two fixes (the MCP status code and Esc in dialogs), and one open question. Not tested here: a real Claude conversation, the installer, updates, and the Docker and log features of the LoopUp extension against real containers.
  • The README now says what it is for, with specific situations instead of a feature list, and real screenshots from the running app.

Major changes

Options and the pattern behind it

The pattern follows the Fluent app settings guidance: group related settings under headers, one card per setting (icon, title, one line, control at the right), an expander for sub-options that is never nested deeper than one level, a scrollable page about 1000px wide at most. Sources: Guidelines for app settings and the SettingsExpander discussion.

Toggles are now always the rounded pill (40 by 24), with a gap before the label. This is a rule, and the one checkbox in the app that was really a setting became a switch, in two places.

Rules added

  • What to avoid in the guidelines: your list as A1 to A15 (looks machine-made) and B1 to B11 (bad in any style), adapted: body text 14px, dim text 13px and never under 12px, controls 30 or 36px for a mouse, checked at 1440, 760 and 375px.
  • Toggle: always the pill switch, 40 by 24, with a gap of 8px before the label. Never a square track or a checkbox for on and off.
  • Settings pages: layout, section head, group heading, setting card, one-level expander, status badges, actions, empty states, wording.
  • Found twice: a button does not center its content for you (A5), a badge says an exception (A9), a page of several sections has no filled button and empty lists hide their bulk row (B3), a narrow window gets a rail that opens over the page (B10), dialogs close with Esc and take focus, prose in documentation pages keeps its full stops.
  • Process: when you call a design bad, the rule is updated in the same change (saved as a standing note).

Open items and things to know

  • Nothing is committed. About 135 paths changed in this repository, and the LoopUp extension repository has changes too (the Projects page, wording, a switch).
  • The LoopUp extension has to be built again and imported again to get its fixes: dotnet build in its repository, then Options, Extensions, Import.
  • extensions/Calculator in this repository is an untracked leftover project that was not made in this round. It is not part of any change here and was left alone.
  • Fields are 32px high and buttons 36px, so a field and a button on one row differ by a few pixels. A global change broke the sidebar search and the model select, so it was reverted. It needs a proper pass on the input styles.
  • The question card and the approval card were not tried with a screen reader.
  • The Home What's New list is a short static list in Shell/WhatsNew.cs. It has to be edited by hand for each release.
  • The "Change All tools to Home" request: the sidebar already said Home everywhere in this repository, so there was nothing to change.
